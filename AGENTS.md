# AGENTS.md

Instructions for coding agents working in this repository. Humans are welcome
to read it too — nothing here is addressed only to a machine.

Read [`docs/SPEC.md`](docs/SPEC.md) before changing anything. It is the source
of truth for what this site does and why, and it names the tests that cover
each of its requirements. `README.md` is the shorter way in.

## Everything written here is in English

Source, identifiers, comments, documentation, test names, commit messages,
branch names, pull request titles and bodies, issue titles and bodies, review
comments, and replies to review comments. All of it, always, in English.

Conversation with the maintainer may happen in Spanish. The artifacts do not:
a comment on a pull request is an artifact, and so is a reply to a reviewer.
The rule is about who reads this repository — Mostro is worked on across
several languages, and a thread nobody outside one of them can follow is a
decision taken in private in a public place.

The one exception is the translation catalogues under `src/i18n/`, which are
by definition not in English: `en.ts` is the source catalogue and the four
others are translations of it. Their *keys*, their types in `strings.ts`, and
every comment around them stay English.

If you find yourself about to write Spanish into a commit, a PR or a GitHub
comment, write it in English instead. If it is already there, fix it.

## What this project is

A static site that reads signed Nostr events and renders figures from them.
There is no server and no build-time data fetch: the site ships code, and the
data arrives at runtime over WebSocket, verified in the reader's browser.

Two properties everything else serves, and neither is negotiable in a patch:

**A reader trusts one pubkey, not a host.** Every figure on screen came from
an event whose signature was checked in the browser that drew it. The
publisher key is baked in at build time; nothing may read a trust anchor from
the page's host, a query string or a relay.

**The site never invents a number.** `null` is absence and renders as absence,
never as a zero. An inferred figure is marked as inferred. A figure nothing
published is a third thing and says so. A panel whose proof failed shows the
failure and no figure at all. An empty state is a claim: do not make it until
the documents behind it have actually answered.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite dev server, against the real relays |
| `npm test` | Unit and integration tests |
| `npm run test:coverage` | The same, with the thresholds enforced |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint |
| `npm run format:check` | Prettier, read-only (`npm run format` writes) |
| `npm run build` | Typecheck, then static output to `dist/` |
| `npm run check:size` | The bundle against its budget |
| `npm run test:e2e` | Playwright |

Before opening or updating a pull request, all of these pass:
`format:check`, `lint`, `typecheck`, `test`, `build`, `check:size`. CI runs
the same set, so a red PR is a round trip nobody needed.

## How code is written here

- **Tests first.** `src/nostr/` and `src/model/` — where a bug is silent — are
  held at 100% on lines, branches and functions; the rest at 80%.
  `npm run test:coverage` enforces both. Tests are named for the behaviour
  they pin, not for the function they call, and are arranged Arrange–Act–Assert.
- **Small files, organised by domain.** Under 400 lines. Extract rather than
  append.
- **Pure where it can be.** Deciding *what* to render is a pure function of
  the bytes received and the clock; the relay layer never touches the DOM and
  a renderer never decides what belongs on screen.
- **Immutable data.** Return new values; do not mutate what you were handed.
- **Comments say why.** The what is in the code. A comment that restates the
  line above it is noise; one that records the bug a line prevents, or the
  contract it keeps, is why the next person does not reintroduce it.
- **Absence is explicit.** No silent catch, no `?? 0` standing in for a figure
  nobody published.

## Things that bite

- **`src/nostr/canonical.ts`** re-serialises a payload the way the daemon
  hashed it, not the way it arrived. It is the only module allowed to produce
  those bytes, and its test runs over the real signed events. Read the note in
  `README.md` before touching it.
- **Fixtures are real events.** `tests/fixtures/snapshot/` holds signed events
  byte for byte as they travel, regenerated by `scripts/fetch-fixtures.mjs`.
  Do not hand-edit one: an edited event fails its own signature, which is the
  point.
- **Five catalogues.** A new user-facing string means a key in
  `src/i18n/strings.ts` and a real translation in all five of `en`, `es`, `pt`,
  `it`, `fr`. The catalogue tests check that none is blank, that every
  interpolation places its argument, and that no locale is quietly still
  English.
- **Accessibility is a requirement, not a polish pass.** WCAG 2.2 AA: semantic
  HTML, real tables with headers, no meaning carried by colour alone, and
  `prefers-reduced-motion` honoured.

## Git and GitHub

- Branch from `main`; never commit to it directly.
- Conventional commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`,
  `perf:`, `ci:`. The subject says what changed; the body says why it needed to.
- A pull request describes the change, the reasoning, and a test plan a
  reviewer can run. Mark what you could not verify — an unverified step said
  plainly is worth more than a checked box that was not.
- Answer review comments. Fix what is real, and say briefly why for what is
  not; a finding you disagree with still deserves a reply.
- In English. See the top of this file.
